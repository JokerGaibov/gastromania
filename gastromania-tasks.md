# Gastromania: очередь задач

Рабочий файл для пошаговой доработки сайта. Источник требований: `gastromania-spec.md`.
Технический аудит и дизайн-система: `main.md`.

---

## Правила работы (соблюдать всегда)

1. **Одна задача за раз.** Не браться за следующую, пока текущая не принята.
2. **Перед началом задачи** перечитать соответствующий раздел `gastromania-spec.md`.
3. **После каждой задачи:** `npm run build` должен проходить без ошибок и без новых warning.
4. **После успешной сборки:** остановиться, коротко отчитаться что сделано и какие файлы затронуты, дождаться подтверждения. Не переходить к следующей задаче самостоятельно.
5. **Коммит** делается после подтверждения, отдельным коммитом на задачу.
6. **Не рефакторить лишнего.** Если по ходу видно проблему вне задачи, записать её в раздел «Найдено по ходу» внизу файла, но не чинить.
7. **Не выдумывать контент.** Если нужны реальные данные ресторана (адрес, телефон, цены, тексты), спросить, а не подставлять заглушки.
8. **Секреты.** `service_role` ключ Supabase не попадает в клиентский код и в репозиторий. В `NEXT_PUBLIC_*` только `anon` ключ. `.env.local` обязан быть в `.gitignore`.
9. Отмечать выполненные задачи галочкой в этом файле.
